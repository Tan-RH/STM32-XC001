# XC001 构建、烧录、网页升级指令说明

本文档用于说明 XC001 工程常用的构建、烧录、网页升级和版本号管理流程。

当前工程采用 Stage0 + Application + Recovery 的启动布局：

| 固件区域 | 地址 | 说明 |
|--|--:|--|
| Stage0 | `0x08000000` | 上电后首先执行，负责判断并跳转到 App 或 Recovery |
| Application | `0x08020000` | 主应用程序，网页升级实际更新的是这个区域 |
| Metadata | `0x081A0000` | 升级状态、CRC、版本等元数据 |
| Recovery | `0x081E0000` | 恢复/安装程序，用于处理网页升级后的固件安装 |

## 一、构建前准备

在 PowerShell 中进入工程根目录：

```powershell
cd E:\STM32\XC001
```

确认 `make` 和 ARM GCC 可用：

```powershell
make --version
arm-none-eabi-gcc --version
```

如果命令找不到，需要先把工具链加入 `PATH`。示例：

```powershell
$env:PATH = "D:\Program Files (x86)\GnuWin32\bin;$env:PATH"
$env:PATH = "D:\Program Files (x86)\Arm\GNU Toolchain mingw-w64-i686-arm-none-eabi\bin;$env:PATH"
```

查看当前软件版本号：

```powershell
make version
```

版本号来源：

```c
Core/Inc/xc001_config.h
#define XC001_SOFTWARE_VERSION "Vx.x.x"
```

后续生成的版本化文件名会使用这里的版本号。

## 二、常用构建指令

### 1. 构建网页升级固件

```powershell
make dfu
```

等同于：

```powershell
make app
```

输出文件：

| 文件 | 用途 |
|--|--|
| `Debug/XC001.hex` | 当前 App HEX |
| `Debug/XC001.bin` | 当前 App BIN |
| `Debug/XC001_<版本号>.hex` | 带版本号的 App HEX |
| `Debug/XC001_<版本号>.bin` | 带版本号的 App BIN，网页升级使用这个文件 |

网页升级时请选择：

```text
Debug/XC001_<版本号>.bin
```

不要上传 `.hex`，也不要上传 `Factory.hex`。

### 2. 构建 Bootloader

```powershell
make bootloader
```

输出文件：

| 文件 | 用途 |
|--|--|
| `Bootloader/build/XC001_Bootloader.hex` | 当前 Bootloader HEX |
| `Bootloader/build/XC001_Bootloader_<版本号>.hex` | 带版本号的 Bootloader HEX |

Bootloader HEX 内部包含：

- Stage0
- Recovery

### 3. 构建工厂烧录整包

```powershell
make factory
```

输出文件：

| 文件 | 用途 |
|--|--|
| `Bootloader/build/XC001_Factory.hex` | 当前工厂整包 |
| `Bootloader/build/XC001_Factory_<版本号>.hex` | 带版本号的工厂整包 |

新板首次烧录建议使用：

```text
Bootloader/build/XC001_Factory_<版本号>.hex
```

该文件已经合并了 Stage0、Application、Recovery 和升级元数据。

### 4. 一次性构建 Bootloader 和 App

```powershell
make all
```

等同于：

```powershell
make bootloader
make app
```

## 三、新板首次烧录步骤

推荐方式：直接烧录工厂整包。

1. 打开 STM32CubeProgrammer。
2. 连接 ST-Link。
3. 选择工厂整包：

   ```text
   Bootloader/build/XC001_Factory_<版本号>.hex
   ```

4. 执行全片擦除并烧录。
5. 烧录完成后复位 PCB。

注意：

- 新板首次烧录可以使用全片擦除。
- 已经安装 Bootloader 的板子，如果只想更新应用，不要再全片擦除。
- 网页升级只上传 App `.bin`，不要上传 Factory `.hex`。

## 四、网页升级步骤

1. 先执行：

   ```powershell
   make dfu
   ```

2. 打开设备网页：

   ```text
   http://<PCB_IP>/
   ```

3. 选择升级文件：

   ```text
   Debug/XC001_<版本号>.bin
   ```

4. 点击升级。
5. 等待网页显示升级完成/设备重启。

网页升级文件选择规则：

| 文件 | 是否可用于网页升级 | 说明 |
|--|--:|--|
| `Debug/XC001_<版本号>.bin` | 是 | 正确文件 |
| `Debug/XC001_<版本号>.hex` | 否 | 不是网页升级输入 |
| `Bootloader/build/XC001_Bootloader_<版本号>.hex` | 否 | Bootloader 不能通过网页升级 |
| `Bootloader/build/XC001_Factory_<版本号>.hex` | 否 | 工厂整包用于烧录器，不用于网页 |

## 五、清理目录后的注意事项

如果按“目录只保留 hex/bin”的要求清理过：

- `Debug` 目录只保留 `.hex` / `.bin`
- `Bootloader/build` 目录只保留 `.hex` / `.bin`

那么 `Debug` 目录里的 CubeIDE 自动生成 makefile、中间 `.o/.d/.elf/.map/.list` 文件会被删除。

此时如果再次执行：

```powershell
make dfu
```

可能会因为 `Debug/makefile` 不存在而失败。

解决方式：

1. 在 STM32CubeIDE 中重新 Build 一次工程，让 CubeIDE 重新生成 `Debug/makefile` 和相关 `subdir.mk`。
2. 然后回到 PowerShell 执行：

   ```powershell
   make dfu
   make bootloader
   make factory
   ```

如果 CubeIDE 重新生成的 `subdir.mk` 带有当前命令行 GCC 不支持的参数，根目录 `Makefile` 会在 `make dfu` 前自动调用：

```powershell
python Tools/sanitize_cube_makefiles.py Debug
```

该脚本会自动移除不兼容的：

```text
-fcyclomatic-complexity
```

## 六、IP 和密码相关说明

当前约定：

- 固件网页升级不需要密码。
- 修改 IP 地址等网络参数需要密码。
- 修改 IP 地址密码为：

```text
GTS
```

默认网络参数：

| 项目 | 默认值 |
|--|--|
| IP | `192.168.1.10` |
| 子网掩码 | `255.255.255.0` |
| 网关 | `192.168.1.1` |
| UDP SCPI 端口 | `4000` |
| HTTP 端口 | `80` |

## 七、常见问题

### 1. `make dfu` 报 `Debug/makefile: No such file or directory`

原因：`Debug` 目录被清理，只剩 `.hex/.bin`，CubeIDE 生成的构建文件已经不存在。

处理：

```text
先用 STM32CubeIDE Build 一次工程，再执行 make dfu。
```

### 2. `arm-none-eabi-gcc: error: unrecognized command-line option '-fcyclomatic-complexity'`

原因：CubeIDE 生成的 makefile 使用了命令行 GCC 不支持的参数。

处理：

```powershell
python Tools/sanitize_cube_makefiles.py Debug
make dfu
```

正常情况下，根目录 `make dfu` 会自动执行该清理脚本。

### 3. 网页升级后 PCB 卡死

优先检查上传文件是否正确：

```text
必须上传 Debug/XC001_<版本号>.bin
```

不要上传：

- `.hex`
- `Bootloader.hex`
- `Factory.hex`

### 4. 直接烧录后 PCB 不启动

优先确认烧录文件：

```text
新板 / 全片擦除后烧录：Bootloader/build/XC001_Factory_<版本号>.hex
网页升级：Debug/XC001_<版本号>.bin
```

不要把网页升级 `.bin` 当成新板完整固件烧录，也不要把 Factory `.hex` 上传到网页升级。
